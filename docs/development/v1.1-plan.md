# v1.1 development plan

## Goals

- Complete the Home eye animations and XiaoZhi state presentation.
- Standardize touch, BMI270, and audio interactions.
- Restore a usable SoftAP provisioning and recovery flow on hardware.
- Add a clear hardware self-test experience.
- Improve Wi-Fi, NTP, weather, and error-state handling.
- Optimize UI performance for the QSPI display.
- Keep simulator and hardware behavior visually consistent.

## Phases

### 1. Home and XiaoZhi states

- Centralize Idle, Listening, Thinking, Speaking, Sleeping, Error, and Stopped states.
- Verify wake, conversation, reconnect, Goodbye, and sleep transitions.
- Ensure temporary server and BMI270 emotes return to the correct base state.

### 2. Touch, BMI270, and audio

- Verify short press, long press, and wake behavior on the Home screen.
- Keep gesture-triggered emotes non-blocking and state-aware.
- Verify activation and Goodbye audio without duplicate playback.

### 3. SoftAP provisioning and recovery

- Diagnose the existing hardware SoftAP path from `WifiProvisioning`, the Wi-Fi
  service, and the board HAL instead of replacing the UI flow.
- Verify both entry paths: automatic provisioning when no saved network can
  connect, and explicit entry from the WLAN SoftAP QR screen.
- Make the AP discoverable and connectable from a phone, with the displayed
  SSID, password, security mode, and QR payload matching the actual AP.
- Complete provisioning end to end: receive credentials, stop SoftAP, reconnect
  in station mode, persist the network, and update the WLAN UI without stale
  Connected or Available Network content.
- Define predictable cancellation and retry behavior when leaving the SoftAP
  screen, disabling WLAN, rebooting, or performing Factory Reset.
- Add simulator regression coverage for lifecycle and UI binding, then perform
  a hardware test using a phone before completing the phase.

Completion criteria:

- SoftAP is visible and accepts the advertised credentials.
- QR and manual connection both use the same real SoftAP configuration.
- Successful provisioning returns the device to station mode and survives reboot.
- Cancel, timeout, retry, WLAN toggle, and Factory Reset do not leave SoftAP or
  station state stuck.

### 4. Hardware self-test

- Cover display, touch, speaker, microphone, BMI270, BQ27220, charging, Wi-Fi,
  NTP, memory, and flash.
- Present each result as Pass, Fail, or Not tested with actionable failure text.

### 5. Network and online services

- Stabilize Wi-Fi scanning, reconnect, and status transitions.
- Improve NTP and weather loading, timeout, retry, and offline presentation.

### 6. QSPI UI performance and parity

- Measure frame time and memory use on hardware before further tuning.
- Remove avoidable redraws and preserve the hardware-specific circular clipping.
- Run simulator self-tests and visual regression checks after UI changes.
